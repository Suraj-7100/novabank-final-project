# Bank API: Go + PostgreSQL on AWS (Terraform)

```
cmd/api/            entrypoint
internal/config     env config
internal/db         pgx pool + embedded SQL migrations (run on startup)
internal/auth       JWT (HS256) + middleware
internal/store      all SQL, incl. the transfer transaction
internal/api        Gin handlers
terraform/          VPC, RDS, ECR, ALB, ECS Fargate, Secrets Manager
```

## Run locally
```bash
docker compose up --build        # API on :8080, Postgres on :5432
```

## API (amounts are integer minor units: paise)
All routes except `/auth/*` and `/healthz` need `Authorization: Bearer <token>`.
Deposits, withdrawals and transfers also need the user's 6-digit `pin`.

| Method | Path | Body / notes |
|---|---|---|
| POST | /auth/register, /auth/login | `{email, password}` returns `token` |
| GET | /me | `{user, account}`; `user.profile_complete` / `user.has_pin` drive onboarding |
| PUT | /me/profile | `{full_name, handle, phone}`; first save opens the primary account |
| PUT | /me/pin | `{pin}` to set; `{pin, current_pin}` to change |
| GET | /handles/:handle | `{handle, full_name}` to confirm the recipient |
| GET | /accounts, /accounts/:id | balances |
| POST | /accounts/:id/deposit, /withdraw | `{amount, pin}` |
| POST | /transfers | `{to_handle, amount, note?, pin}` (`from_account_id` optional) |
| GET | /accounts/:id/transactions | `limit` (1-100), `offset` |

PIN rules: 6 digits, bcrypt-hashed, no repeated digits or obvious sequences. After 5 wrong
tries it locks for 15 minutes (HTTP 423, `retry_after_seconds`). Wrong PIN is HTTP 403 with `attempts_left`.

Every money movement publishes an event (`internal/notify`). Locally it is just logged; with
`SNS_TOPIC_ARN` set it goes to SNS, where the real-time layer picks it up.
Set `CORS_ORIGIN` to the web app's origin in production.

Transfers lock both account rows (`SELECT ... FOR UPDATE`, ordered by id) inside one
transaction, so concurrent transfers can't overdraw or deadlock.

## Deploy
Needs Terraform >= 1.5, AWS CLI (configured), Docker.
```bash
cd terraform
terraform init
terraform apply -target=aws_ecr_repository.app     # 1. create the registry first

REPO=$(terraform output -raw ecr_repository_url)    # 2. build + push (amd64 matters on Apple Silicon)
aws ecr get-login-password --region ap-south-1 | docker login --username AWS --password-stdin ${REPO%%/*}
docker build --platform linux/amd64 -t $REPO:latest ..
docker push $REPO:latest

terraform apply                                     # 3. everything else
curl $(terraform output -raw api_url)/healthz
```
Update the app later: push a new image, then
`aws ecs update-service --cluster <ecs_cluster> --service <ecs_service> --force-new-deployment`.

`terraform destroy` removes everything (RDS skips the final snapshot by default; see variables).

## Before real use
HTTPS (ACM cert + 443 listener), one NAT per AZ, `db_multi_az`, deletion protection and
final snapshot, rate limiting on login, idempotency keys on transfers. The DB password
and JWT secret are generated by Terraform, so they also exist in the Terraform state file;
keep state in an encrypted remote backend (S3 + DynamoDB lock).


## Frontend authentication note
The `web/index.html` page now uses the Go API and PostgreSQL; it does not use the old browser-only demo database. Accounts previously created only in the old `localStorage` demo are not present in PostgreSQL and cannot log in through the API. Register those email addresses again in the connected app, or use an account already registered through `POST /auth/register` against this backend.

## AWS event notifications
Terraform creates an SNS topic and grants the ECS task role only `sns:Publish` on that topic. The API reads `SNS_TOPIC_ARN` and publishes ledger events when configured. This topic alone does not push live events into browsers: a subscribed Lambda/API Gateway WebSocket delivery component must be deployed and connected before claiming cross-device real-time notifications.
